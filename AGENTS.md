# F-Layer Development Protocol

## Project Principles

- Architecture first.
- Evidence-driven development.
- Reproducible changes.
- Minimal unnecessary complexity.
- Preserve contracts and history.

## Workflow

Before changes:
- Understand current architecture.
- Identify source of truth.
- Define acceptance criteria.

After changes:
- Run tests.
- Validate behavior.
- Update documentation when required.

## Security

Never commit secrets, private keys, credentials or environment-specific sensitive data.

## Git

Use small atomic commits with clear English imperative messages.

## Reviews

Changes must be traceable through issues, pull requests and validation results.
