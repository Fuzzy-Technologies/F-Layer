# Правила документации {#documentation-contracts}

F-Layer использует [шаблон документации Fuzzy Technologies](https://github.com/Fuzzy-Technologies/FuzzyRoutines/tree/develop/docs/documentation-blueprint): MkDocs Material, mkdocstrings-python и Griffe со статическим обнаружением из установленного wheel. Тема расширяется отслеживаемыми конфигурацией, CSS и SVG. Созданный HTML остаётся временным и неотслеживаемым.

## Обнаружение API {#api-discovery}

Каждый модуль Python установленного пакета `flayer`, не являющийся частным, получает страницу API; `flayer.__main__` — явно поддерживаемое исключение из правила путей с подчёркиванием. Частные модули и вспомогательные функции доступны только в исходниках, с указанием причин. Обнаружение читает синтаксис и не импортирует исполняемый код. Защита импорта прерывает сборку при попытке выполнения пакета. Весь установленный пакет должен совпадать с инвентарём и байтами исходников, кроме байткода. Публичные определения и вызываемые протоколы требуют точных якорей HTML; каждая страница API связывается с соответствующим исходником `develop`.

Каждый отслеживаемый файл соответствует ровно одному явному правилу покрытия. Все канонические Markdown-файлы, включая политики, правила выпуска, ADR, шаблоны и точки входа репозитория, отображаются и должны быть достижимы из английской начальной страницы. Тесты, инструменты, workflow, примеры, ресурсы и конфигурация имеют объяснённое назначение, а не выдуманную документацию API. Локализованные наложения отображаются обёрткой с явным состоянием проверки. [Контракт покрытия](https://github.com/Fuzzy-Technologies/F-Layer/blob/develop/docs/development/documentation-coverage.md) определяет границу и машиночитаемые свидетельства.

Каждая отслеживаемая Markdown-таблица выровнена по содержимому столбцов. Проверка исходников проверяет читаемость до публикации; она сохраняет экранированные вертикальные черты, ячейки с кодом, маркеры выравнивания и буквальные примеры в блоках кода.

Английские авторские страницы используют отслеживаемый реестр единиц локализации. Созданные единицы API используют временный инвентарь с теми же устойчивыми ID символов и версионными хешами источника. Состояние их переводов явно равно `missing`; инвентарь не создаёт переводов или проверок.

## Язык и проверка {#language-and-review}

Английский язык канонический. Зарегистрированные черновики на русском и упрощённом китайском можно отображать многоязычной обёрткой с явными баннерами состояния проверки. Отсутствующие или устаревшие единицы используют актуальный английский текст. Навигация и баннеры различают состояния `draft`, `review`, `stale`, `missing`, `approved`; автоматизация никогда не создаёт одобрений от человека.

Каждый существующий перевод записывает `basedOnSourceHash` — фактически использованный английский источник. Обновление канонического реестра не скрывает устаревший черновик. Проверка языков человеком и фактическая публикация Pages остаются невыполненными.

Для допустимого `approved` нужны устойчивый ID единицы, совпадающий хеш канонического источника, путь перевода и ответственные редакционная и техническая проверки человеком. Автоматизация может обнаружить изменения и создать записи `missing`, но не создаёт одобрений. Терминология находится в согласованных глоссариях языков.

## Публикация {#publication}

Pull request и `develop` создают скачиваемые артефакты предпросмотра и свидетельств. Только событие `push` ветки `master` может развернуть проверенный артефакт Pages. Публикация документации отделена от публикации пакета.

Публичные маршруты: `/F-Layer/en/`, `/F-Layer/ru/`, `/F-Layer/zh-CN/`. Корневой адрес открывает английский справочник. Неизменяемая документация выпуска не заявляется до стабильного релиза.

[ADR 0004](https://github.com/Fuzzy-Technologies/F-Layer/blob/develop/docs/adr/0004-documentation-platform.md) фиксирует генератор, проверку, хеши источника, fallback и границы публикации.
