# CLI и результаты диагностики {#cli-and-diagnostic-results}

CLI модуля доступен в базовом пакете. Все команды справки работают без сети. `check` выполняется локально; HTTP-диагностика требует явного адреса.

```bash
python -m flayer --help
python -m flayer check --format json
python -m flayer status --format text
python -m flayer health --help
python -m flayer benchmark --help
```

| Команда     | Наблюдение                                            | Сеть                           |
| ----------- | ----------------------------------------------------- | ------------------------------ |
| `check`     | Доступность локального Python и пакета.               | Не используется.               |
| `status`    | Локальные проверки и поддержка наблюдений провайдера. | Не используется в базовом CLI. |
| `health`    | Один ответ явно выбранного HTTP(S)-адреса.            | Только переданный адрес.       |
| `benchmark` | Ограниченные HTTP(S)-измерения времени передачи.      | Только переданный адрес.       |

Верхнеуровневый `status` сообщает `unsupported` для состояния провайдера, пока адаптер наблюдений не подключён к этой команде. Он не объявляет пустое облако здоровым. `status` жизненного цикла — отдельная команда с явной областью, введённая задачей #20; см. [первое развёртывание](first-deployment.md).

## Проверки явного адреса {#explicit-endpoint-probes}

Выберите адрес, к которому у вас есть разрешённый доступ. Примеры используют зарезервированный `example.com`; замените его на выбранный HTTP(S)-адрес:

```bash
python -m flayer health --endpoint https://example.com/ --timeout 3 --format json
python -m flayer benchmark --endpoint https://example.com/ --timeout 3 --count 3 --bytes 65536 --format json
```

Учётные данные, строки запроса и фрагменты в URL отклоняются. Проверка сертификата TLS остаётся включённой; перенаправления и поиск прокси отключены. Адрес, содержимое ответа и исходные исключения не включаются в отчёты. Таймаут ограничен 30 секундами на измерение, число измерений — 10, объём — 1 MiB. Работа конечна, включая ошибки DNS, TLS и чтения. Результаты описывают эту проверку с этой машины, а не SLA провайдера, гарантированную скорость VPN или успешное развёртывание.

## Код завершения {#exit-status}

| Код | Значение                                          | Действие оператора                                     |
| --- | ------------------------------------------------- | ------------------------------------------------------ |
| `0` | Все запрошенные проверки имеют `ok`.              | Используйте записанные наблюдения.                     |
| `1` | Хотя бы одна проверка предупреждает или неудачна. | Изучите структурированные результаты.                  |
| `2` | Неверные аргументы или ограничения.               | Исправьте аргументы перед повторением.                 |
| `3` | Наблюдение устарело.                              | Получите новые свидетельства.                          |
| `4` | Запрошенное наблюдение не поддерживается.         | Передайте адрес или используйте реализованный адаптер. |

JSON-отчёты содержат `schema_version`, `command`, общий `status` и отдельные `checks`. Общая серьёзность не скрывает неудачных наблюдений. Для автоматизации проверяйте код завершения и структурированные состояния; наличие JSON-отчёта не означает успех.
