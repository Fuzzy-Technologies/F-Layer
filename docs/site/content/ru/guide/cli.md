# Командная строка и диагностика {#cli-and-diagnostic-results}

Командная строка входит в пакет F-Layer. Справка и команда `check` работают
без сети. Для проверки HTTP-сервиса нужно передать его адрес.

```bash
python -m flayer --help
python -m flayer check --format json
python -m flayer status --format text
python -m flayer health --help
python -m flayer benchmark --help
```

| Команда     | Что проверяет                                        | Сетевые запросы              |
| ----------- | ---------------------------------------------------- | ---------------------------- |
| `check`     | Установлены ли Python и F-Layer.                     | Нет.                         |
| `status`    | Локальную среду и наличие данных о состоянии облака. | В базовой команде нет.       |
| `health`    | Ответ указанного HTTP(S)-сервиса.                    | Только к переданному адресу. |
| `benchmark` | Время HTTP(S)-запросов и передачи заданного объёма.  | Только к переданному адресу. |

Обычный `status` пока не получает состояние облачных ресурсов и возвращает
для этой проверки `unsupported`. Для уже созданного развёртывания используйте
`lifecycle status`: ему нужны план, файл состояния и профиль `yc`.
Пример есть в [руководстве по развёртыванию](first-deployment.md).

## Проверка HTTP-сервиса {#explicit-endpoint-probes}

Замените `https://example.com/` на адрес сервиса, который хотите проверить
и к которому у вас есть разрешение обращаться:

```bash
python -m flayer health --endpoint https://example.com/ --timeout 3 --format json
python -m flayer benchmark --endpoint https://example.com/ --timeout 3 --count 3 --bytes 65536 --format json
```

В URL нельзя передавать имя пользователя, пароль, параметры запроса или
фрагмент после `#`. Проверка TLS-сертификата включена; перенаправления и
автоматическое использование прокси отключены. Отчёт не содержит адрес
сервиса, тело ответа или полный текст внутренней ошибки.

Одна проверка длится не более 30 секунд, число измерений ограничено 10,
объём ответа — 1 MiB на измерение. Ограничения действуют и при ошибках DNS,
TLS или чтения ответа. Результат показывает доступность сервиса с той машины,
где запущена команда. По нему нельзя судить о скорости VPN или готовности
всего облачного развёртывания.

## Коды завершения {#exit-status}

| Код | Значение                                      | Что сделать                                               |
| --- | --------------------------------------------- | --------------------------------------------------------- |
| `0` | Все запрошенные проверки завершились с `ok`.  | Используйте результаты отчёта.                            |
| `1` | Есть предупреждение или ошибка.               | Найдите причину в списке `checks`.                        |
| `2` | Неверные аргументы или превышены ограничения. | Исправьте параметры команды.                              |
| `3` | Данные о состоянии устарели.                  | Повторите проверку.                                       |
| `4` | Запрошенная проверка пока не поддерживается.  | Укажите адрес сервиса или используйте подходящий адаптер. |

JSON-отчёт содержит `schema_version`, `command`, общий `status` и список
отдельных `checks`. Ошибка в любой проверке отражается в общем статусе.
В скриптах проверяйте и код завершения, и статусы проверок: сам факт получения
JSON не означает успешного результата.
