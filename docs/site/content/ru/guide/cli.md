# Командная строка и диагностика {#cli-and-diagnostic-results}

Командная строка входит в пакет F-Layer. Справка и команда `check` работают
без сети. Для проверки HTTP-сервиса нужно передать его адрес.

```bash
python -m flayer --help
python -m flayer check --format json
python -m flayer status --format text
python -m flayer health --help
python -m flayer benchmark --help
```

| Команда     | Что проверяет                                        | Сетевые запросы              |
| ----------- | ---------------------------------------------------- | ---------------------------- |
| `check`     | Установлены ли Python и F-Layer.                     | Нет.                         |
| `status`    | Локальную среду и наличие данных о состоянии облака. | В базовой команде нет.       |
| `health`    | Ответ указанного HTTP(S)-сервиса.                    | Только к переданному адресу. |
| `benchmark` | Время HTTP(S)-запросов и передачи заданного объёма.  | Только к переданному адресу. |

Обычный `status` пока не получает состояние облачных ресурсов и возвращает
для этой проверки `unsupported`. Для уже созданного развёртывания используйте
`lifecycle status`: ему нужны план, файл состояния и профиль `yc`.
Пример есть в [руководстве по развёртыванию](first-deployment.md).

## Проверка HTTP-сервиса {#explicit-endpoint-probes}

Замените `https://example.com/` на адрес сервиса, который хотите проверить
и к которому у вас есть разрешение обращаться:

```bash
python -m flayer health --endpoint https://example.com/ --timeout 3 --format json
python -m flayer benchmark --endpoint https://example.com/ --timeout 3 --count 3 --bytes 65536 --format json
```

В URL нельзя передавать имя пользователя, пароль, параметры запроса или
фрагмент после `#`. Проверка TLS-сертификата включена; перенаправления и
автоматическое использование прокси отключены. Отчёт не содержит адрес
сервиса, тело ответа или полный текст внутренней ошибки.

Одна проверка длится не более 30 секунд, число измерений ограничено 10,
объём ответа — 1 MiB на измерение. Ограничения действуют и при ошибках DNS,
TLS или чтения ответа. Результат показывает доступность сервиса с той машины,
где запущена команда. По нему нельзя судить о скорости VPN или готовности
всего облачного развёртывания.

## Коды завершения {#exit-status}

| Код | Значение                                      | Что сделать                                               |
| --- | --------------------------------------------- | --------------------------------------------------------- |
| `0` | Все запрошенные проверки завершились с `ok`.  | Используйте результаты отчёта.                            |
| `1` | Есть предупреждение или ошибка.               | Найдите причину в списке `checks`.                        |
| `2` | Неверные аргументы или превышены ограничения. | Исправьте параметры команды.                              |
| `3` | Данные о состоянии устарели.                  | Повторите проверку.                                       |
| `4` | Запрошенная проверка пока не поддерживается.  | Укажите адрес сервиса или используйте подходящий адаптер. |

JSON-отчёт содержит `schema_version`, `command`, общий `status` и список
отдельных `checks`. Ошибка в любой проверке отражается в общем статусе.
В скриптах проверяйте и код завершения, и статусы проверок: сам факт получения
JSON не означает успешного результата.

## Экспорт существующего VPN-устройства {#export-an-existing-vpn-device}

После развёртывания, когда клиентские файлы уже созданы, экспортируйте одно устройство:

```bash
flayer vpn export --project ~/flayer-vpn --device laptop --protocol amneziawg --output ~/flayer-export-awg --qr
flayer vpn export --project ~/flayer-vpn --device laptop --protocol vless-reality --output ~/flayer-export-vless --qr --format json
```

В каждой выходной папке появляется `device-laptop-PROTOCOL/`: манифест принадлежности,
исходные файлы протокола, `amnezia.vpn` и, с `--qr`, пронумерованные кадры
`amnezia-qr-01.svg`. Без `--qr` экспортируются только файлы. Для AWG сохраняется
`amneziawg.conf`; для VLESS — `client.json`, `import.txt` и существующий нативный
ключ подключения. В Android AmneziaVPN импортируйте `amnezia.vpn`, вставьте ключ
подключения или отсканируйте **все кадры собственным сканером AmneziaVPN** за один
сеанс импорта. Нативный профиль AWG содержит и исходную конфигурацию, и отдельные
поля версии 3.1, включая `HeaderProtectionKey`, параметры дополнения пакетов и
маршруты. Обычные клиенты WireGuard эти параметры обфускации не поддерживают.

Экспорт работает локально: не обращается к облаку или серверу, не создаёт новые
учётные данные и не проверяет существование сервера. Он проверяет принадлежность
и содержимое всей исходной группы файлов, затем создаёт приватные папки `0700`
и файлы `0600`. Укажите новую выходную папку с существующей родительской папкой
либо существующую приватную папку. Идентичный экспорт можно повторить; изменённые,
чужие файлы или другой состав вывода не перезаписываются. Для изменения опции QR
нужна другая выходная папка. Хранилище исходных артефактов нельзя использовать
как выходную папку. Нативный экспорт AWG поддерживает один или два DNS-сервера;
большее число отклоняется, поскольку оболочка нативного подключения имеет два
поля DNS. При ошибке исходные файлы сохраняются.

Профили и QR дают доступ от имени устройства: храните их приватно. Отчёт содержит
пути, но не ключи или URL подключения. Успех экспорта не подтверждает соединение:
после импорта проверьте DNS, маршруты, выходной IPv4 и поведение IPv6 клиента.
Нативная схема и формат кадров соответствуют
[исходникам AmneziaVPN 5.0.3.0](https://github.com/amnezia-vpn/amnezia-client/tree/de93650a90739b87bb47a632872ea9d0adc9412f).

## Диагностика Shorts и медиа Telegram {#investigate-shorts-and-telegram-media}

Работающий handshake, обычное видео или Speedtest не объясняют сбой другого
приложения. Низкое потребление памяти службами и отсутствие OOM не подтверждают
проблему памяти. До изменения ресурсов соберите наблюдения за одним и тем же событием.

1. Запишите версии Android/AmneziaVPN/YouTube/Telegram, сеть (Wi-Fi или мобильная),
   настройки DNS/Private DNS, режим VPN/TUN и исключения приложений. Для сравнения
   отключите отдельный прокси Telegram, затем восстановите его прежнюю настройку.
   Проверьте один и тот же Short и один и тот же медиафайл без локального кэша:
   напрямую, если возможно, только AWG, затем только VLESS. Повторите три раза,
   чередуя порядок протоколов; фиксируйте начало UTC, успех/ошибку и длительность.
2. Сравните приложение YouTube и тот же Short в браузере. Проверьте совпадение
   публичного IPv4 с ожидаемым адресом сервера, использование нужных DNS и отсутствие
   обхода туннеля по IPv6. Wi-Fi и мобильную сеть проверяйте отдельно; меняйте
   по одной настройке. Повторяемое отличие сужает гипотезу, но не доказывает причину.
3. Во время каждой попытки снимите состояние перезапусков/выхода служб, доступную
   память, недавние OOM, загрузку каждого ядра и сетевые ошибки/потери. Записывайте
   прирост счётчиков за интервал, а не общие значения. На ВМ с долей CPU проверьте
   steal time. Speedtest и субъективная скорость загрузки сами по себе не доказывают
   нехватку CPU.
4. Сохраните короткий [лог клиента AmneziaVPN](https://docs.amnezia.org/documentation/instructions/logging/)
   вокруг воспроизведения. Журналы доступа и ошибок Xray в F-Layer по умолчанию
   отключены: системный журнал жизненного цикла не объяснит отдельный запрос.
   При необходимости отдельно согласуйте ограниченный по времени эксперимент
   с [логированием Xray](https://xtls.github.io/en/config/log.html) на тестовом стенде,
   сохранив и восстановив исходные файлы и состояние службы. Адреса назначений,
   идентификаторы пользователей и сырые логи оставляйте приватными; наружу передавайте
   только очищенные результаты и время. Не изменяйте молча подготовленные файлы
   или их манифест.
5. Если данные указывают на DNS, UDP/QUIC или MTU пути, проверяйте гипотезу отдельно
   на клиенте/стенде. [QUIC использует UDP](https://www.chromium.org/quic/), но это
   не означает, что именно QUIC вызвал сбой Shorts. Не считайте передачу UDP в
   VLESS и AWG одинаковой. Если клиент/браузер позволяет, проведите ограниченное
   сравнение с TCP; оно не объясняет автоматически поведение приложения Android.
   Профиль AWG уже использует MTU 1280: не увеличивайте его и не меняйте глобальные
   MSS/правила firewall без данных о пути. Для изменения политики предпочтителен
   новый явно настроенный тестовый профиль; повторите затронутые проверки DNS,
   маршрутизации и IPv6.

Для каждой гипотезы запишите: подтверждается, отвергнута или не установлена.
Эта инструкция сама по себе не разрешает менять рабочий VPN или продлевать платный стенд.
