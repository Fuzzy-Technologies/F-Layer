# Быстрый старт {#quick-start}

Сначала попробуйте F-Layer локально, затем выберите проверку сервиса или
облачное развёртывание. Нужны **Python 3.11+ и Git**. Для первой проверки
облачный аккаунт не требуется.

## 1. Установите стабильный выпуск {#1-install-the-stable-release}

```bash
git clone https://github.com/Fuzzy-Technologies/F-Layer.git
cd F-Layer
git checkout v1.2.1
python -m venv .venv
```

Активируйте окружение в своей консоли:

| Консоль                  | Команда                      |
| ------------------------ | ---------------------------- |
| Linux/macOS bash или zsh | `source .venv/bin/activate`  |
| Windows PowerShell       | `.venv\Scripts\Activate.ps1` |
| Windows Command Prompt   | `.venv\Scripts\activate.bat` |

```bash
python -m pip install .
```

Решения проблем с окружением — в разделе [установки](installation.md).

## 2. Выполните первую проверку {#2-run-your-first-check}

```bash
python -m flayer --help
python -m flayer check --format json
```

Ожидаемый результат: `"command": "check"`, `"status": "ok"`, код завершения **0**.
Команда подтверждает, что Python и F-Layer доступны. Она не обращается к
сервисам, не входит в облачный аккаунт и не создаёт сервер.

В справке `{status,check,health,benchmark,lifecycle}` означает **выберите одну
команду**. Скобки вводить не нужно. Например, `python -m flayer check --help`
показывает параметры `check`.

## 3. Выберите сценарий {#3-choose-a-real-scenario}

**Проверить HTTP-сервис.** Укажите адрес, к которому у вас есть разрешение обращаться:

```bash
python -m flayer health --endpoint https://example.com/ --timeout 3 --format json
```

Замените пример своим сервисом. Команда отправляет HTTP-запрос;
`"status": "ok"` и код `0` означают, что проверка пройдена. При ошибке
будет ненулевой код и структурированный результат.
[Руководство CLI](cli.md) объясняет статусы, ограничения и измерение времени.

**Развернуть SSH-шлюз в Yandex Cloud.** В инструкции
[первого развёртывания](first-deployment.md) описано, как подготовить конфигурацию
и план ресурсов, а затем явно разрешить облачные изменения. Нужны облачный
аккаунт и аутентифицированный профиль `yc`; ресурсы могут быть платными.
Шлюз пересылает трафик через SSH к настроенным адресам. Это не готовый VPN-профиль.

**Встроить в приложение на Python.** Начните со
[справочника API](../../en/api/index.md) и [конфигурации](configuration.md).

Обычный `status` пока возвращает `unsupported` (код `4`) для наблюдения за
облаком. Чтобы проверить реальное развёртывание, используйте `lifecycle status`
с его планом, файлом состояния и профилем провайдера. Локальная проверка
не подтверждает готовность облачного сервера.
