# Быстрый старт {#quick-start}

Создайте приватный VPN-проект, разверните один сервер в Yandex Cloud и подключите
устройство по **AmneziaWG** или **VLESS Reality**. F-Layer создаёт облачные ресурсы,
устанавливает обе службы и готовит отдельные настройки подключения для каждого
устройства.

## 1. Установите F-Layer {#1-install-f-layer}

Чтобы поручить эти шаги ассистенту с доступом к терминалу, скопируйте задание из
[быстрого старта с ИИ](ai-operator.md). Там описаны установка, вопросы к
пользователю, согласование платных ресурсов и проверка реального подключения.
Команды ниже предназначены для самостоятельного выполнения.

Нужны Linux или WSL, Python 3.11+, OpenSSH (`ssh` и `ssh-keygen`) и
[официальный CLI Yandex Cloud](https://yandex.cloud/ru/docs/cli/quickstart).
Скачайте wheel F-Layer 2.0.0 и проверьте его хеш по инструкции
[Установка](installation.md). Создайте и активируйте виртуальное окружение,
затем установите wheel с дополнением `vpn`. Укажите путь к скачанному файлу:

```bash
FLAYER_WHEEL=/absolute/path/to/f_layer-2.0.0-py3-none-any.whl
python -m pip install "${FLAYER_WHEEL}[vpn]"
flayer project --help
flayer vpn --help
```

Дополнение устанавливает криптографическую библиотеку для локального создания
ключей. Git и Docker не нужны.

## 2. Настройте проект {#2-set-up-the-project}

Настройте `yc` по официальной инструкции и посмотрите доступные профили:

```bash
yc config profile list
flayer project init ~/flayer-vpn
```

Откройте `~/flayer-vpn/project.toml`. Перед подготовкой замените следующие значения:

| Настройка                                | Что указать                                                                                                           |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `identity.project`, `stack`, `owner_id`  | Имена проекта, развёртывания и владельца.                                                                             |
| `identity.scope_id`                      | ID каталога Yandex Cloud, в котором нужно создать ресурсы.                                                            |
| `cloud.yc_profile`                       | Настроенный профиль `yc` с правом создавать и удалять вычислительные и сетевые ресурсы в этом каталоге.               |
| `cloud.zone_id`, `cloud.image_id`        | Зону доступности и ID образа Ubuntu 24.04 для **amd64**.                                                              |
| `cloud.management_cidrs`                 | Текущий внешний IPv4-адрес администратора с `/32`; замените адрес из примера.                                         |
| `devices`                                | Имена устройств и уникальные адреса внутри туннеля; начните с `laptop` / `10.66.0.2` из примера.                      |
| `vless.target_host`, `vless.server_name` | Доступный сайт с TLS 1.3 / HTTP/2 и действительным сертификатом для указанного имени сервера. Имя в шаблоне — пример. |

Для первой проверки оставьте исходные настройки: режим полной маршрутизации
IPv4; настройку клиента рассмотрим ниже. Перед подключением отключите IPv6
в настройках VPN-клиента или на устройстве: эта версия не маршрутизирует IPv6. Значение `ipv6_policy` в TOML
не меняет настройки операционной системы устройства.

Каталог проекта содержит закрытые SSH- и VPN-ключи. Храните его вне Git и общих
каталогов, сохраняйте ограничения прав доступа и сделайте закрытую резервную
копию. Определите нужные устройства и маршруты до следующего шага.

## 3. Подготовьте и разверните сервер {#3-prepare-and-deploy}

```bash
flayer vpn prepare --project ~/flayer-vpn
flayer vpn deploy --project ~/flayer-vpn --allow-mutation --scope-confirm YOUR_FOLDER_ID
flayer vpn status --project ~/flayer-vpn
```

Вместо `YOUR_FOLDER_ID` укажите точное значение `identity.scope_id`. Команда
`prepare` создаёт локальные файлы без обращения к облаку. `deploy` создаёт сеть,
подсеть, группу безопасности, публичный адрес, загрузочный диск и ВМ, затем
устанавливает обе VPN-службы. Пока эти ресурсы существуют, Yandex Cloud
начисляет плату за их использование.

Перед передачей закрытых файлов F-Layer сверяет SSH-ключ ВМ с ключом, полученным
через API Yandex Cloud именно для ВМ этого проекта. Значение `services-active`
в отчёте означает, что серверные процессы работают; подключение клиента ещё
нужно проверить следующим шагом.

## 4. Подключите устройство {#4-connect-a-device}

Используйте файлы своего устройства. Для стандартного устройства `laptop`:

| Протокол      | Что импортировать                                                         | Настройка клиента                                                                                                                              |
| ------------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| AmneziaWG     | `~/flayer-vpn/artifacts/device-laptop-amneziawg/amneziawg.conf`           | Импортируйте файл в клиент с поддержкой AmneziaWG 3.1 и включите туннель. Обычный клиент WireGuard не понимает дополнительные поля протокола.  |
| VLESS Reality | Ссылку из `~/flayer-vpn/artifacts/device-laptop-vless-reality/import.txt` | Импортируйте в совместимый клиент, например v2rayN или v2rayNG. Для трафика всего устройства отдельно настройте DNS, маршруты и режим VPN/TUN. |

Ссылка VLESS не переносит в клиент все настройки DNS и маршрутов. Для самого
Xray в том же каталоге есть `client.json`: он содержит настройки DNS и маршрутов
для прокси и открывает локальный порт `127.0.0.1:10808`. Приложения должны использовать
`socks5h://127.0.0.1:10808`; трафик остальных приложений автоматически туда
не направляется. Совместимые клиенты, раздельная маршрутизация и подробности
протоколов описаны в руководствах [AmneziaWG](../../../../architecture/amneziawg.md)
и [VLESS Reality](../../../../architecture/vless-reality.md).

Проверяйте протоколы **по одному**. Откройте HTTPS-сайт через каждый клиент,
убедитесь, что видимый внешний IPv4-адрес совпадает с адресом сервера, и проверьте
DNS и IPv6. Успешный импорт настроек или работающая серверная служба ещё
не подтверждают, что трафик идёт через туннель.

## 5. Восстановите или удалите развёртывание {#5-recover-or-remove-the-deployment}

Если создание облачных ресурсов прервалось, сохраните те же файлы проекта
и выполните:

```bash
flayer vpn recover --project ~/flayer-vpn --allow-mutation --scope-confirm YOUR_FOLDER_ID
```

Перед повторной попыткой прочитайте отчёт. Если установка внутри ВМ прервалась
на полпути, может понадобиться проверка и восстановление файлов с ключами
и настройками, созданных F-Layer. Восстановление облачных ресурсов не разрешает
перезаписывать неизвестную серверную конфигурацию.

Чтобы удалить облачные ресурсы этого проекта:

```bash
flayer vpn destroy --project ~/flayer-vpn --allow-mutation --scope-confirm YOUR_FOLDER_ID
```

Проверьте результат команды и каталог в облаке. Локальные ключи, клиентские
файлы и состояние остаются в каталоге проекта. Сохраняйте их до подтверждения
полной очистки.

В этой версии настройки подготовленного проекта неизменяемы. Чтобы добавить
устройство или поменять маршруты, сначала удалите старое развёртывание,
используя неизменённый проект, а затем создайте **новый приватный каталог
проекта** с нужными настройками. Добавление и отзыв устройств, а также ротация
ключей без пересоздания пока недоступны в CLI.

## Следующие шаги {#next-steps}

Yandex Cloud — реализованный облачный провайдер. Для других облаков нужен
отдельный адаптер. Существующие сервисы можно проверять через
[CLI-диагностику](cli.md); для интеграции из Python см.
[Конфигурацию](configuration.md) и [справочник API](../api/index.md).
Ответственные за релиз записывают результаты реальных облачных и клиентских
проверок по [процедуре приёмки VPN](../../../../development/vpn-release-acceptance.md).

В справке фигурные скобки, например `{prepare,deploy,status,destroy,recover}`,
означают **выберите одну команду**. Вводить сами скобки не нужно.
